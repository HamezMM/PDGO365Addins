# BracketFields — setup

Word VSTO add-in. Adds a **Home ▸ Bracket Fields ▸ Fill [Fields]** button that:

1. Scans the active document for every `[bracketed]` parameter field — body, tables,
   headers/footers (every section), footnotes/endnotes, comments, and text boxes
   (including text boxes inside headers/footers).
2. Opens a dialog that walks through each **unique** field one at a time (Back / Next,
   or click any field in the list). Each field shows how often it appears and a snippet of
   surrounding text.
3. On **Finish** / **Replace All**, replaces every occurrence of each filled field —
   brackets included — with the entered value. Fields left blank are not touched.
   The whole fill is **one Undo step** (Ctrl+Z once reverts it).

## What counts as a field

- `[` + one or more characters + `]` on a single line, with no nested brackets.
  `[Client Name]`, `[ Fee ]`, `[Date-1]` are fields; `[]`, `[   ]`, and a `[` that isn't
  closed before the end of the paragraph are ignored.
- Matching is **exact and case-sensitive**: `[Date]` and `[date]` are two separate fields.
- Tokens longer than 255 characters are ignored (Word's Find limit; almost certainly prose).
- The replacement takes the formatting of the field it replaces.

## Build & run

Prerequisites are the same as every add-in in this repo — Office workload installed and
the shared PDG Code Signing `.pfx` imported into `CurrentUser\My`. See
`..\SheetToTxt\SETUP.md` ("Signing certificate") and `..\CLAUDE.md` §2–3.

1. Open `..\PDGO365Addins.sln` in Visual Studio 2022, set **BracketFields** as the startup
   project, press **F5**. VS builds, registers the add-in under
   `HKCU\Software\Microsoft\Office\Word\Addins\BracketFields`, and launches Word.
2. Open a document with `[fields]` and click **Home ▸ Fill [Fields]**.

Command line:
```
"C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" ^
  BracketFields.csproj /p:Configuration=Debug
```
A plain build already registers the add-in for the current user; `/t:Clean` unregisters it.

## Files

| File | Role |
| --- | --- |
| `ThisAddIn.cs` | Startup/shutdown; registers the XML ribbon; re-evaluates the button on `DocumentChange`. |
| `ThisAddIn.Designer.cs` / `.xml` | VSTO plumbing (Word host). Regenerated by the VSTO designer. |
| `Ribbon/BracketFieldsRibbon.xml` | Ribbon markup (Home tab button). Embedded resource. |
| `Ribbon/BracketFieldsRibbon.cs` | `IRibbonExtensibility` — thin callbacks: scan → dialog → replace → summary. |
| `DocumentStories.cs` | Enumerates every text story (incl. header/footer shapes). Shared by scan and replace. |
| `BracketFieldScanner.cs` | Regex over each story's text → unique fields in order of first appearance. |
| `BracketFieldReplacer.cs` | Find loop per story, sets `Range.Text`, wrapped in one `UndoRecord`. |
| `BracketField.cs` | Model: token, occurrences, context snippet, entered value. |
| `UI/FillFieldsForm.cs` | The walkthrough dialog (built in code, no designer file). |

## Known limits

- A field split across a Word field code / content-control boundary may be counted by the
  scan but not replaced (the summary's occurrence count will then be lower than expected).
- With **Track Changes on**, replacements are tracked as normal revisions, and text inside
  a *deleted* revision is still scanned.
- A protected document (Restrict Editing) is refused with a message; unprotect it first.
